# ADR-0001：采用四层记忆与信息治理

- 状态：已接受
- 范围：Hermes 助手与 Debian 旁路由项目

## 背景

把用户偏好、项目现状、操作流程、历史记录和强制安全规则全部写入全局记忆，会导致上下文膨胀、事实过期、跨项目污染和执行约束不可靠。

## 决定

采用四层结构：

1. 核心记忆：少量用户偏好与跨项目稳定事实；
2. Holographic Memory：按需召回的长期事实和决策背景；
3. 项目文件与 Skills：项目权威资料和可复用方法；
4. 运行时强制规则：项目上下文、校验器、权限、备份、回滚和验收。

Holographic Memory 使用显式写入，禁用自动抽取，防止把临时聊天内容未经核验写成长久事实。

## 后果

- 新会话的固定上下文更小；
- 需要在任务开始时主动读取项目来源并加载 Skill；
- 外部记忆只作为检索线索，不能覆盖实时状态；
- 安全要求必须尽量由程序和工具边界执行；
- 临时进度留在会话、TODO 或项目任务文件中，不进入长期记忆。

## 验证

- `hermes memory status` 显示 Holographic provider 可用；
- `USER.md` 与 `MEMORY.md` 不含临时任务状态和凭据；
- 项目根目录存在 `.hermes.md`；
- 本 ADR 与 `docs/authority-and-memory.md` 可被仓库读取；
- 敏感信息扫描无命中。
