# 权威来源与记忆分层

本项目采用四层信息治理，避免将实时状态、项目事实、操作方法和用户偏好混入同一个全局记忆文件。

## 1. 核心记忆

Hermes 的 `USER.md` 与 `MEMORY.md` 只保存少量、长期稳定、跨会话有价值的信息。

- `USER.md`：用户偏好、授权边界、长期验收原则。
- `MEMORY.md`：跨项目环境事实、通用约定、反复验证过的经验。

禁止写入：任务进度、当前 PID、临时端口状态、备份编号、一次性修复结果、日志、凭据。

## 2. 外部长期记忆

使用 Hermes Holographic Memory 保存按需召回的长期事实和决策背景。当前策略：

- 显式写入，不启用会话结束自动抽取；
- 只保存有来源、可复用、不会很快过期的事实；
- 项目事实若能从仓库或生产配置读取，不重复复制为权威事实；
- 与实时系统或项目文件冲突时，外部记忆自动降级为历史线索。

## 3. 项目文件与 Skills

### 项目文件

项目仓库记录设计、配置模型、代码、测试和发布状态。生产运行状态仍以实机为准。

权威文件：

- `README.md`：项目目标与当前成熟度；
- `docs/architecture.md`：目标架构与数据路径；
- `docs/roadmap.md`：版本范围；
- `SECURITY.md`：安全边界；
- `docs/decisions/`：长期架构决策；
- 代码、模板和测试：实际实现。

### Skills

Skills 保存可重复执行的方法，包括触发条件、前置检查、工具、步骤、安全边界和验证方法。Skills 不保存某次任务的完成状态。

## 4. 运行时强制规则

高风险要求不能只依赖记忆文字。项目通过项目上下文规则、管理脚本、原生配置校验、权限边界、备份和回滚执行强制约束。

最低要求：

1. 生产变更前读取实时状态；
2. 变更前备份；
3. Mihomo、MosDNS、AdGuard Home 与 nftables 使用原生校验；
4. TProxy 变更同时验证监听器、nftables、`ip rule` 和路由表；
5. DNS 隐私验收检查公网明文 53；
6. 失败自动回滚或保留已验证的旧配置；
7. 不把 `active` 等同于端到端可用；
8. 不向报告、仓库、记忆或外部事实库写入凭据。

## 权威优先级

发生冲突时按以下顺序处理：

```text
实时系统状态与生产配置
> 项目代码、配置、测试和正式文档
> 当前官方文档
> 已核验的外部长期记忆
> Skills 中的方法性经验
> 历史会话
> 未核验推断
```

## 任务召回顺序

```text
理解任务
→ 检查当前项目规则与原始来源
→ 加载对应 Skill
→ 查询相关外部长期记忆
→ 必要时检索历史会话
→ 执行
→ 用真实输出验证
→ 仅把长期稳定内容写回正确层级
```

不机械加载全部资料，只读取与当前任务相关的来源。

## 长期保存门槛

信息通常至少满足以下两项才进入长期记忆：

- 跨会话仍然有效；
- 未来会重复使用；
- 忘记后用户需要再次纠正；
- 会改变后续处理方式；
- 来源明确且已核验；
- 不容易从权威来源重新读取。

密码、Token、API Key、订阅凭据和节点密钥永不进入任何记忆层。
